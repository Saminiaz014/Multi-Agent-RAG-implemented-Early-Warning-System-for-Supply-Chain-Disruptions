# Evidence Provenance Matrix (A7)

**All five regions use synthetic scenario data, grounded in documented historical
events, generated by `src/benchmark/scenario_generator.py`. Hormuz is the only
region with real, API-connected data in the live production pipeline
(`src/ingestion/*_connector.py`) — the EVAL01 benchmark itself, for all five
regions including hormuz, is synthetic throughout.** No baseline, ablation, or
aggregation result anywhere in `results/` is measured against real historical
sensor data; every scenario is `materialize_scenario()` output driven by the YAML
files this document catalogs.

Two distinct kinds of "evidence" are tracked separately below, because conflating
them overstates provenance:

- **Region-level strength classification** (`DOMINANT`/`STRONG`/`MODERATE`/`WEAK`/
  `ABSENT`/`EXCLUDED`) — from `config/benchmark/{region}.yaml`'s header comments.
  Describes how strongly a domain's real-world driver is documented for that
  region *in general*, across all of that region's researched events.
- **Scenario-level target evidence tag** (`documented` / `extrapolated` / `null`) —
  from the specific `P_CRIT` scenario YAML's inline comments. Describes whether
  *this specific numeric target*, on the synthetic generator's normalized 0–1 (or
  z-scored, for `market`) scale, is lifted directly from a sourced figure
  (`documented`), derived by scaling/converting a real figure onto that scale
  (`extrapolated`), or the domain doesn't move in this scenario at all (`null`).
  **A domain can be region-level `DOMINANT`/`STRONG` and still be
  scenario-level `extrapolated`** — the real-world driver being well-documented
  does not mean a literal number exists that maps directly onto this benchmark's
  synthetic 0–1 scale; converting a PSI reading or a percentage decline into that
  scale is itself an extrapolation step, however well-grounded the source figure
  is. The two columns below answer different questions; do not read a `STRONG`
  region-level rating as implying a `documented` scenario-level tag.

Source files, per region: `config/benchmark/{region}.yaml` (region-level),
`config/benchmark/scenarios/{region}_P_CRIT.yaml` (scenario-level, cited per row),
`data/region_research/{region}_disruption_patterns.json` (underlying primary
sources, bab_el_mandeb/panama/suez/malacca only — hormuz has no equivalent
region-research file in this repository, see the Hormuz row below).

## Malacca's news target — the corrected version of the task's claim

The task framed this as: *"Malacca's news target is the clearest placeholder case
— extrapolated-null across all four documented events."* **Checked directly against
`data/region_research/malacca_disruption_patterns.json`'s four `events[].signal_effects.news`
entries, and this is only partly accurate — reported as found, not smoothed to
match the prompt's framing:**

| event | news `value` | news `evidence` tag |
|---|---|---|
| 2015 Southeast Asian haze | `null` | `extrapolated` |
| 2019 Southeast Asian haze | `null` | `extrapolated` |
| 2019–2024 chronic piracy/armed-robbery baseline (SOMS) | "ReCAAP ISC issues periodic public 'Incident Alert' bulletins... when incident clusters occur" | **`documented`** |
| Late-2024 Pulau Cula piracy escalation | "ReCAAP ISC issued dedicated 'Incident Alert' bulletins... (e.g. IA 01-2024, IA 03-2024)" | **`documented`** |

News is `extrapolated`-with-a-`null`-value for the **two haze events only**; it is
`documented` (qualitatively — bulletin issuance, not a volume/sentiment index) for
the **two piracy events**. `malacca_P_CRIT.yaml` specifically draws on the 2015 haze
event, so for *this scenario*, the task's characterization is directionally
correct — its news target genuinely is the clearest placeholder case in the
benchmark (see `malacca_P_CRIT.yaml`'s own header: the initial `0.50` target was
found to rival the evidence-anchored `disaster` domain's peak and was stepped down
to `0.35` by re-measurement, not by any sourced figure). But "extrapolated-null
across all four documented events" is not accurate to the underlying evidence file
as a whole — half of the four events (the piracy ones) have a real, if
unquantified, documented news signal. This distinction matters because
`malacca_N_DECOY` uses `geopolitical` (piracy-domain), not `news` — the piracy
events' `documented` news evidence and P_CRIT's haze-derived `extrapolated-null`
news target describe two structurally different scenarios in the same file, not one
uniformly-weak domain.

## Which targets are evidence-anchored vs. tier-convention placeholders (summary)

**Directly evidence-anchored (a literal sourced figure maps ~1:1 onto the target):**
- `bab_el_mandeb_P_CRIT.routing` (`0.85` = the documented 85% diversion rate).
- `panama_P_CRIT.shipping` (`0.50` drop = the documented `36→18` announced floor).
- `suez_P_CRIT.shipping` (`0.05` ≈ documented near-total physical closure, with a
  noted numerical-implementation adjustment away from a literal `0.0`).

**Tier-anchored / scaled from a real figure, but not a literal 1:1 mapping
(`extrapolated`):** every other active-domain target in bab_el_mandeb, panama,
suez, and malacca's `P_CRIT` files — the large majority of numeric targets in this
benchmark. This includes domains whose real-world driver is region-level
`DOMINANT`/`STRONG` (panama's disaster, malacca's disaster, bab_el_mandeb's
geopolitical) — a strong real-world evidence base does not by itself produce a
literal number on this generator's synthetic scale; that conversion step is what
makes these `extrapolated` rather than `documented`.

**Untagged (predates the audit-tag convention):** every domain in
`hormuz_P_CRIT.yaml`. Hormuz's underlying crisis is independently verified as a
real, documented 2026 event (see prior project verification via web search,
referenced in this repository's own commit history for the Prompt 3-ALT pass), but
that verification is not recorded as per-domain inline citations in the scenario
YAML itself the way the other four regions' files are — an asymmetry in
documentation rigor across the five files, not a claim that hormuz's numbers are
any less real-world-grounded than the others'.

**Clearest tier-convention placeholder:** `malacca_P_CRIT.news` (`0.35`) — see the
dedicated section above. No source anchors this number to any real figure; it was
set purely by re-measuring against another domain's evidence-anchored peak until a
margin was satisfied.

**Structurally absent, by evidence not by omission:** `panama_P_CRIT.geopolitical`
(evidence file states no geopolitical driver applies at all) and every region's
`suez_P_CRIT.{routing,geopolitical}` / `malacca_P_CRIT.{shipping,geopolitical,routing}`
combinations listed `null` in the table above — each has an explicit, cited reason
in its scenario YAML's header, not a silent gap.
